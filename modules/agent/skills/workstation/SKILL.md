# Workstation substrate — development workflow

## When to Use

**Use when**: working on the workstation repo (savioserra/workstation; each host's checkout path is recorded in its `hosts/local/machine.json` `checkout`) — the nixpkgs-native substrate (`modules/<domain>/`, flake.nix, the shim, hosts/, tests/nix/). `docs/architecture.md` at HEAD is the structure's home; the substrate's loop, battery and conventions live in `references/nix-substrate.md`.

## The loop

- Verification: `sh .github/scripts/check.sh` with nix + the flakes env (identity gate, history-prose gate, shell checks, shim dispatch test, eval read gate) — fast and foreground-safe. Format with nixfmt before landing; eval host legs separately (check.sh does not) — the CI loop: every `nixosConfigurations.*.config.system.build.toplevel.drvPath`, `darwinConfigurations.*` same, `homeConfigurations.*.activationPackage.drvPath`; a new user service must ship on BOTH legs — prove it on the BUILT generation of the real host key (`ls <gen>/home-files/.config/systemd/user/<unit>`; `home-manager.users.<u>.launchd.agents` on darwin), never by `config.systemd.user.services` alone: home-manager's systemd module is inert for `home.username == "root"`, so the option evaluates while no unit ships (fix: references/nix-module-system-pitfalls.md). Likewise prove a system-plane service with `services.<x>.enable` on the real leg — a leg that never sets `workstation.enable` keeps the whole system module inert. Full mechanics and pitfalls live in the nix-substrate reference.
- NEVER put the battery's verification command inside a `| filter` pipeline that is chained with `&&` into follow-up actions (`sh check.sh | tail -1 && git push`) — the pipeline masks the battery's exit code with the filter's, so a FAILED battery sails through the chain and gets pushed. Run the battery as its own statement and read its output after, or set `-o pipefail` first. This pushed a red state twice in one session before it was named.
- The same masking has two more forms: a zero-match `grep -c` exits 1 and silently halts every later step of a `&&` chain (embed greps in `if`/`||` deliberately), and `ls | grep name` never sees DOTFILES — a present `.bashrc` reads as absent and you 'repair' a file that exists. Probe existence with `test -e` / `ls -a`, and when a chain dies early, the remaining steps never ran — never report their outputs.
- Read the actual state before reporting coverage: one matching path does not mean 'all covered' — re-query the full set and state the comparison explicitly (a 1-of-12 set misread as fully covered produced a false green verdict).
- Consumer smokes must exercise the consumer, not the binary: for a capability whose consumer is a network session (mosh, ssh, anything dialing a peer), `--version` on PATH proves nothing — run the session bootstrap end-to-end (for mosh: the `ssh <host> -- mosh-server new …` leg, then the UDP leg) before claiming the capability works. Report smoke evidence at the level the operator will actually use, or say plainly what was and was not tested. mosh into a bash standalone-HM host: the ssh leg runs `bash -c` with no home-manager session vars (HM's `.bashrc` returns for non-interactive shells; Arch bash reads no user file for ssh commands) — no profile PATH and no `LOCALE_ARCHIVE_2_27`, so the nix mosh-server is either not found or dies with 'needs a UTF-8 native locale' on any non-C locale; the terminal domain's `mosh` wrapper's `--server` sources `hm-session-vars.sh` first. Reproduce the ssh leg on the target with the OPERATOR'S client locale — `env -i HOME=$HOME USER=$USER LANG=<his LANG> PATH=/usr/local/bin:/usr/bin bash -c '<the exact --server string> new -l LANG=<his LANG> -- true'` (expect `MOSH CONNECT`); `C.UTF-8` is built into glibc and hides the locale failure. Then the UDP leg with a pinned port: `mosh-server new -p <port> -- sh -c 'echo OK $LANG; sleep 30'` on the target and `MOSH_KEY=<key> script -qec "stty rows 40 cols 120; mosh-client <ip> <port>" <log>` here — `script`'s pty has 0 rows and mosh-client asserts without the `stty`.
- A node connecting to ITS OWN MagicDNS name bypasses Tailscale SSH: tailscaled only intercepts port-22 traffic arriving over `tailscale0`, so a loopback-origin connection to the node's own tailnet IP falls through to the local sshd — with empty `authorized_keys` and password auth on, `ssh root@<self>` asks for a password and every mosh bootstrap to self dies there. Diagnose session failures by reading `journalctl -u tailscaled` (interactive sessions log `--has-tty=true`, command bootstraps log `--cmd=` — an absence of `--cmd=` entries means the bootstrap never reached tailscaled) alongside the sshd auth-failure lines, and attribute the source IP via `tailscale status --json` before concluding the transport is broken.
- Fresh installs are ONE line: `curl -fsSL <repo>/raw/main/install.sh | sh` (the guarded `sh -c "$(curl ...)"` form is the documented recommendation). The repository is `savioserra/workstation`. install.sh ensures nix, clones to `WORKSTATION_CHECKOUT` (default `~/workstation`, no fallback path), and chains `workstation init`. A host whose checkout predates the default dir moves it ONCE by hand, rewrites `hosts/local/machine.json` `.checkout` to the new path, then applies — the path is embedded in the generation (the launcher's `WORKSTATION_CHECKOUT` default), so a move without an apply leaves every later outside-checkout invocation pointing at a dead dir. The identity gate allowlists the project's own repository path (a public repo address is not host identity) — filter the exact repo-path string in the gate command and keep the rc semantics (leftover matches fail, a clean tree passes); match the path on any host prefix (raw.githubusercontent vs github.com).
- Renaming the repository: `gh repo rename <new> -R <owner>/<old> --yes` (GitHub then redirects clone/raw/push from the old name — a redirect is not a contract, so re-point `origin` on every checkout, the worktrees included, in the same pass). One commit sweeps the tree: README/install URLs, install.sh's default repo URL, the release workflow's artifact prefix, and the identity gate's allowlisted repo-path string (the battery reds on the old path). Grep case-sensitively for the owner/repo string, never case-insensitively — a former name can collide with the nvim distribution's identifiers (`LazyVim`, `lazyvim.plugins.*`) and flood the grep. Existing hosts keep their checkout DIRECTORY unless the operator rules the move (see the fresh-install bullet for the one-off).
- One atomic conventional commit per landing; repo law and the worker/lead split live in the repo's AGENTS.md — never restate them in cards.
- Converging a host is ONE command: `workstation init` seeds
  `hosts/local/` from `hosts/template/` and captures `hosts/local/machine.json`
  (whiptail dialogs prefilled from detection: host, user, home, system;
  `settings` is a home-manager option tree) and chains the first
  activation; every later update is `workstation apply`, and per-machine
  capability selection is `workstation add|remove <path>` / `workstation
  selected` — paths are option paths (`editor`, `languages/typescript` →
  `workstation.languages.typescript.enable`), set in `settings` by jq;
  `hosts/local/` is gitignored, so the checkout stays clean and pulls never
  conflict. `workstation setup` reruns the entire inquiry (identity dialogs
  prefilled with the current answers, the languages checklist, the fleet
  choice); init asks the languages once. Domains default on, `network` and
  language members default off. WORKSTATION_NO_APPLY=1
  skips the first switch. The user surface is the `workstation` verb alone —
  never hand a user a leg-native verb (nixos-rebuild/darwin-rebuild/home-manager);
  the switch driver is a staged internal detail.
- NEVER split an activation-package build and its path resolution into two nix calls (`nix build --no-link` then `nix eval --raw`) — the second call re-evaluates the dirty working tree, and with any concurrent edit (a card worker, a formatter) it returns a store path the build never produced; the activate then dies with 'not found'. One invocation: `nix build --no-link --print-out-paths <attr>` builds and prints the exact built path.
- When a card worker is in flight in the SAME checkout, its test fixtures may hold `hosts/local/machine.json` — the machine's real capture is then absent from evals. Stash the capture (`~/.hermes/cache/scratch/`) and DEFER `workstation apply` on that host until the card completes: an apply against a fixture identity switches the wrong home config.
- The operator's hostname may differ from the tailscale node name (the OS hostname differs from the tailscale node name): capture uses the DETECTED hostname prefilled in the whiptail dialogs, and the operator corrects it to the canonical name in the dialog — don't silently rewrite the capture after init.
- NEVER boot the VM E2E (QEMU) on a host before checking acceleration: no `/dev/kvm` and no vmx/svm flags (a cloud VM already running under KVM without nested virt) means pure TCG emulation — a NixOS boot pegs every core at 100% for hours. The operator's ruling is absolute: behavioral verification is the CONTAINER lane (references/bare-box-docker-testing.md — the P0-proven docker recipe); the VM lane sits outside the battery.
- Stage with `git add -A -- . ':!.worktrees'` and keep `.worktrees/` in `.gitignore` — the worktrees are registered git worktrees (embedded repos) and land as embedded-repo blobs in history when staged.
- Review and landing gates read FILES, not transcripts: tool output is passed through a display scrubber that masks certain literal patterns, so a string that looks corrupted in a diff, a review finding, or a log tail may be correct on disk — verify programmatically (read the file, probe the URL) before any fix or revert (details in `references/nix-substrate.md`, 'Pitfalls that cost hours').
- Documentation style law: docs and code comments read as tables, bullets and commands — each bullet/cell a noun-phrase fragment, never a full sentence ('The NixOS legs set X' is prose; 'mosh: `home.packages`, `programs.mosh.enable` on NixOS legs' is the shape he keeps) — no narrative prose, no parenthetical asides, no ruling citations, card IDs or dates; describe only the current world, in positive statements (a sentence like 'there is no engine' is still a ghost of the removed thing); history lives in Git history, never in doc prose. User-facing docs (README above all) lead with the motivation and the public surface — what the thing is for, the verbs a user types — and push internals (report attrs, host legs, input wiring) into the references; a README that opens with machinery gets ruled a rewrite. When a surface goes away, purge its mentions in the same pass that drops the code — grep the docs for the old names and rewrite, don't leave a 'leftover ledger' narrative behind. No prose in source code: a comment states what the code does as a terse line or bullets, never why-it-happened ('the X first switch', 'operator instruction', an investigation recap). The battery's history-prose gate fails on dates, card ids, ADDEN''DUM, operator-ruling citations and history words (lega''cy, reti''red, migra''tion, form''erly, no lon''ger, cut''over, chez''moi) — assemble new tokens with `''` splits so the gate's own source never matches — its comment and failure message are scanned too, so word them without the history words — and mutation-test it (plant a word, see it red). Vocabulary of a previous era is history too: old component names ('engine', 'daemon', 'recipe', 'pre-seed'), dead probes that assert an old thing is absent, data roles nothing consumes — remove them, don't reword them. Host/device names the gate cannot know — grep them by hand (see the bootstrap rule below).
- No backward compatibility: the operator wants a stable cut, not a compatibility path. When a landing breaks a shape (machine-file layout, launcher contract), break it cleanly, move each existing host with a one-off out-of-repo step in its pane, and tag a MAJOR release once every reachable host is converged on the tagged sha.
- Before cutting a release, run the README one-liner on a LIVED-IN host the substrate did not create (distro dotfiles, a foreign daemon package, an old checkout): the container e2e starts from a bare home and hides home-manager's 'would be clobbered' refusal and update-path breakage. Test the fresh path by `mv`-ing the old checkout aside (never rm), and keep the e2e planting a distro `.bashrc` before the first switch.
- Machine-specific moves are NEVER repo code: removing the operator's previous app/package install (Tailscale.app, an apt tailscale), a list of formulas dropped from brew, a one-time first switch hook — these fixed ONE machine and become dead weight for every other user. Run them as an out-of-repo runner on that host; the repo only provisions its own surfaces and, at most, detects a conflicting install and stops naming it. Tooling memory/state dirs (`.pi/`, agent-memory, swarm notes) are never source: delete them on sight and keep them in `.gitignore`.
- When the operator rules a deletion ('get rid of it'), land it FIRST as its own commit and push — before any broader sweep you were planning around it; folding it into a bigger pass reads as not having done it.
- Reviewing or critiquing the architecture (research + verdict against nixpkgs-native, flags-select-domains, no cross-domain reach): follow `references/architecture-review.md` — ownership map, eval-cost and instantiation probes on a scratch copy, live read-verb check on a real host, tables-only report in a dir outside the repo, and propose only. Once the operator rules 'implement', follow its 'Implementing the ruled steps' section: one step per commit to `main`, the gate order ending in the container e2e, the old-vocabulary sweep, every host converged before the next step, out-of-repo machine-file move with a dry-run equality proof.
- The container e2e (`tests/nix/run-container.sh`) builds a `git archive HEAD` extraction — uncommitted edits are NOT under test. Commit (locally, amend later) before every e2e run, and never report an e2e result for work that was uncommitted when it ran.
- A FRESH host's first converge also bypasses the shim: until an activation has run once, `workstation apply` answers 'the write plane is the generation's workstation-switch driver and it is not on PATH' — build and run the activation package directly (`nix build --no-link --print-out-paths 'git+file://<checkout>?rev=<HEAD>#homeConfigurations."<user>@<host>".activationPackage' --override-input machine-files path:<checkout>/hosts/local` then `<out>/activate`; discover the key with `nix eval ...#homeConfigurations --apply builtins.attrNames` — WITHOUT the override it answers the template key, which is the wrong one). Afterwards the generation's launcher is on PATH and `workstation apply` works. Guard that HEAD carries the new input first: an older commit ignores the override, falls back to the TEMPLATE machine and builds the wrong key.
- `self.rev` / `self.dirtyRev` vanish whenever an input is overridden (`--override-input machine-files …` always is): name the applied commit from the ref's `?rev=` instead, and keep `workstation.rev` only as the fallback for un-overridden evals.
- Driving whiptail dialogs in a pane: zoom the pane (`tmux resize-pane -Z`) BEFORE the dialogs draw — a dialog drawn in a small tiled pane stays clipped after a resize; before each Enter on a menu, confirm the selection with `tmux capture-pane -p -e | cat -v` (the selected item carries `^[[41m`), since a plain capture shows no highlight and a capture right after Down may predate the redraw.
- Renaming the repository: `gh repo rename <new> -R <owner>/<old> --yes` (GitHub then redirects clone/raw/push from the old name). The reference surfaces to move with it: the identity gate's allowlisted repo-path string in check.sh, install.sh's default repo URL and checkout dir, the README one-liner, the release workflow's artifact prefix, every checkout's `origin` (`git remote set-url`). Existing hosts keep their checkout DIRECTORY — the one-off move procedure lives in the fresh-install bullet above.
- A host reporting an unknown verb/argument for a verb the shim HAS: check `command -v workstation` — a foreign binary in `~/.local/bin` (first on PATH) can shadow the generation's launcher and answer with a foreign program's error (argparse wording is the tell). Move the stale file aside, then `hash -r` in the operator's shells — bash caches the dead path and keeps resolving it until rehashed or a fresh shell.
- A whiptail menu selection in a pane: verify the highlight before Enter — `tmux capture-pane -p -e` shows the selected row in reverse video (`^[[37m^[[41m`), rows render `^[[30m^[[47m`; the dialog may also be wider than the pane, so grep the row and its attributes, not the full line.
- Quoting through `tmux send-keys`: escape sequences like `\x27` land LITERALLY in the target shell (`x27` becomes part of the command and a jq filter dies at column 1) — restructure the quoting (double quotes around the filter, a different delimiter) instead of escaping. When a sent chain dies at its first failing command, everything after `&&` never ran — re-send only the missing tail, and assert the result file afterwards, not the command's rc alone.
- Every whiptail stub in the dispatch gate must answer EVERY dialog kind the shim can ask (a new `--checklist` in init turns every init case into a cancelled run): give stubs a kind-detecting `case` over the flag args, return `--checklist` selections on STDERR (the caller's `3>&1 1>&2 2>&3` swap makes stub-stderr its stdout), and order stub `case` patterns most-specific first — sh takes the FIRST match, so `*"token"*` listed before `*"token."*` swallows the scoped lookup and every per-path answer goes wrong. A stubbed `nix` should answer both the scoped and the unscoped form of every report attr the shim reads.
- whiptail checklist output QUOTES every selected tag (`"elixir" "go"`) — strip quotes (`tr -d '"'`) before membership matching, and make the test stub emit quoted tags so the gate catches it (an unquoted stub passed while real whiptail deselected everything). A deselected default-off member's whole key leaves (`del(.settings.workstation.languages[$n])`), not just `.enable` — deleting only `.enable` strands `{}` entries. And `machine_edit` takes the jq FILTER FIRST, then --arg pairs — args-first garbles into `jq: --arg takes two parameters`.
- Never sed a redirect token inside a test line you are iterating on (`2>"$shim"` truncated bin/workstation to 0 bytes mid-debug): layered seds on the same line stack garbage — rewrite the whole line via the patch tool, and after any sed on a file with a shell entrypoint, `wc -c` it before running gates (a 0-byte shim still passes some gates' setup and fails confusingly later).
- Answering an interactive prompt in a host pane: capture the pane IMMEDIATELY before sending the answer — a prompt that already resolved turns `yes` into a shell command (the `yes` binary floods the pane until Ctrl-C). Verify an unknown ssh host key against the tailnet before accepting: `tailscale status --json` → the peer's `sshHostKeys`, fingerprinted with `ssh-keygen -lf -`.
- Immutable-rootfs linux hosts: disable the read-only rootfs BEFORE install.sh (`steamos-readonly disable` on SteamOS) — Determinate Nix provisions `/usr/local/bin/determinate-nixd` and an immutable rootfs rejects that write mid-install (exit 'Read-only file system'). After ANY interrupted install, probe `ls /nix/var/nix/profiles/` before trusting the installer's receipt: a /nix holding only `nix-installer` + `receipt.json` answers 'already completed' with no store behind it — recover with `/nix/nix-installer uninstall` (answer Y at the plan prompt) then a fresh install.sh run.
- A host that auto-suspends on idle kills long builds WITH the ssh session: wrap installs and applies in `systemd-inhibit --what=sleep workstation apply` — polkit asks a password there; it is the operator's to type, say so and stop. If he declines, a plain apply is fine only while the host stays powered with auto-suspend off.
- An ssh pane whose connection died in the host's sleep hangs SILENTLY: send-keys land invisibly (cursor moves, capture shows a frozen screen), and no error surfaces anywhere. Probe once with a literal `echo` + Enter; if nothing prints, `tmux respawn-pane -k -t <pane> 'ssh <user>@<host>'`. A Tailscale-SSH check-mode host asks a browser approval on the first connection from a source and skips it on later ones — a respawn may hand the operator a login URL.
- Send literal text with `tmux send-keys -l` — without `-l`, long command lines can be dropped or mangled before the separate Enter call, leaving a clean prompt that silently never ran anything.
- A lived-in host's first activation dies on home-manager's clobber guard (`Existing file '~/.local/bin/nvim' would be clobbered`): earlier collisions auto-move to `*.hm-backup`, the fatal one is a foreign shim blocking a path the generation owns — relocate it aside (`<name>.aside`) and re-run the activation. And `workstation setup`/`init` on such a host starts from a FRESH DEFAULT capture (only languages asked once, domains default) — when the operator reports 'everything looks different / my old prompt is gone', the cause is default selections replacing the machine's earlier ones, not a wrong repo: verify `git remote -v` first, then re-select capabilities (`workstation add <path>` / `setup`) and re-apply.
- Homebrew on the darwin leg is a managed dependency through `nix-homebrew` (nixpkgs has no homebrew package): it pins brew via its lock (`brew --version` reads 'shallow or no git repository'; `/opt/homebrew/Library/Homebrew` links into `/nix/store/*-brew-<ver>-patched`), `autoMigrate` takes over an existing install keeping its packages, and nix-darwin's `homebrew.*` declares what it installs — no `onActivation` update/upgrade against a pinned brew.
- Multi-file python edit scripts stop at the first failed assert with the EARLIER files already written: before re-running, read `git diff --stat` and make the rerun idempotent (skip blocks whose result is present) or split the remainder into a new script — re-running blind double-applies or asserts on already-edited text.
- An apply in a host pane that looks stalled: check `ps -eo pid,etime,args | grep -E 'workstation-switch|nix build'` once, then capture the pane again — never loop captures or sleep.
- A landing that moves a tool with a LONG-LIVED SERVER (tmux, gateways, agents) leaves the old-version server running — a switch never restarts it, and a newer tmux client refuses the old server with `open terminal failed: not a terminal` (no code bug). When the operator reports a tool broken after a converge, check skew FIRST: `readlink /proc/<pid>/exe` of the running server vs `command -v <tool>` (tmux renames itself — find it with `ps -eo pid,comm,args | grep '[t]mux'`, comm `tmux: server`; the default-socket owner is the one `<old exe> display -p '#{pid} #{version}'` answers), and reproduce against a fresh server on a scratch socket (`tmux -L zz new -d`, attach inside `script -qec … /dev/null`). Unblock with `/proc/<pid>/exe a`; never kill the server yourself (it holds his sessions and the agent's own converge panes) — `tmux kill-server` is his call. Lead the answer with the workaround and own the cause in one line; asked 'was it a bug', say plainly: not a code bug, an unannounced upgrade gap. Every step report whose lock or channel moves such a tool names the version jump and the restart it needs.
- Designing or debugging module-system surfaces (options, enables, gating, selection flags): read `references/nix-module-system-pitfalls.md` FIRST — every idiom and trap there was exercised against the real module system, including the two silent ones (undeclared config keys are rejected; `mkIf`-false leaves options undefined, and `lazyAttrsOf` keeps phantom leaves).
- First switch on a host: follow `references/host-first-switch.md` — survey-first, preserve-dir relocations, the byte-diff parity proof, consumer smokes with languages composed, and the generated-lua-module/version-floor traps a linux first switch surfaced. darwin-leg bootstrap: `references/host-first-switch-macos.md` (platform-by-uname leg selection, the LnL7 bootstrap ref, the sudo-escalated first switch, the identity-derived key collision).
- Experiments stay OUT of the repo: an evaluation the operator is still ruling on (menu configs, shell-integration sources, ad-hoc tools) lives as host-local state only — hand-edited rc lines labeled evaluation-only, `nix profile install` for tryout binaries, config deltas in the working copy uncommitted (applies build the committed HEAD, so the operator's in-progress payload edits never deploy; `WORKSTATION_WORKTREE=1 workstation apply` deploys the working tree only when he asks to try them). A repo payload edit 'while we're at it' during an evaluation is a violation the operator names loudly; commit only the surfaces the operator has ruled on.
- Renaming an option path (a domain move): grep the WHOLE tree including the system-plane modules and BOTH template legs — the declaring plane and every consumer must move together. A leg that evaluates multiple planes (darwin composes system+home) throws 'option does not exist' on a half-moved rename, while single-plane legs (standalone HM) hide it; the naming must also stay domain-coherent — the system plane keeps the domain's current name, not the pre-move one.
- NEVER `git stash` for a baseline inside a worktree: `refs/stash` is shared by every worktree of the repo, so a push that fails (intent-to-add files refuse: 'not uptodate. Cannot merge') makes the follow-up `pop` apply ANOTHER worktree's stash and spill its untracked files into yours. Baseline with `git archive HEAD | tar -x -C <scratch>` (a path flake: `path:.#...`) instead; if a spill happens, prove the spilled files byte-identical to `stash@{0}^3` and move them to scratch — never drop the foreign stash.
- `pkill -f`/`pgrep -f <pattern>` run through the terminal tool matches the tool's OWN shell (the pattern is in its command line) and kills it. List first with `ps -eo pid,args | grep -F "$a$b"` where the pattern is assembled from variables at runtime.
- check.sh SILENTLY skips its ShellCheck and nixfmt gates when the tools are not on PATH (green with half the gates). Put shellcheck on PATH for the battery (`nix build --no-link --print-out-paths nixpkgs#shellcheck.bin`); run nixfmt yourself over every tracked and new `.nix` before the battery.
- Hermes runtime surfaces (A2A converge, hermes CLI as an activation writer, the token store, the peers hub, the fleet service and its trust rule, long-running shell services under socat, multi-node and whiptail test harnesses): read `references/hermes-a2a.md` first.
- CONVERGED HOSTS ARE THE GOAL; CI COMES LAST. After a landing, apply on every host and prove each with the store-path equality (references/host-first-switch.md, 'The convergence proof') — fresh, never from an earlier reading; never block on, watch or poll CI before the hosts are converged, and never answer 'converged' from an apply receipt alone. Generations build the checkout's COMMITTED HEAD (`git+file://<checkout>?rev=<HEAD>`) with the machine files via `--override-input machine-files path:<checkout>/hosts/local`: uncommitted payload work stays out of the generation and a commit that touches nothing deployed leaves it unchanged — but compute 'want' with that SAME ref + override, never `.#` (a path ref includes the dirty tree and reports false drift). Re-apply every host after every landing that changes a generation. Tagging may precede a green CI run: the release workflow re-runs CI before publishing. When the operator's window holds one pane per host, converge THERE — send each host its pull + apply + store-path-equality one-liner that prints `<host> CONVERGED at <sha>` / `DRIFT want=… live=…` in its own pane (the darwin one is `sudo workstation apply --system` — a bare `workstation apply --system` dies with 'system activation must now be run as root' — and waits on the operator's sudo password) — so the proof is visible where he looks. A zero-diff step (every leg's drvPath equal to the previous HEAD's) leaves every host converged without an apply.
- A first switch that kills its own transport (tailscaled swap, Tailscale.app removal) runs as ONE runner inside a tmux session ON THE TARGET (`tmux new-session -s hostswitch 'sh runner | tee log'`), sudo once with a keepalive, failing safe (a stopped step leaves the previous install serving); verify the far side afterwards from the other host over the services (A2A cards, fleet markers, audit log) until the operator restores the pane. Darwin specifics: references/host-first-switch-macos.md.
- Setup flows belong in the one-line bootstrap: a machine-level choice (identity, fleet start/join/standalone) is asked ONCE by `workstation init` in whiptail, persisted in the machine files, and re-askable through its own verb. Never hardcode the operator's nodes or hosts in the tracked tree — discover them at run time (tailnet status) and let the user pick in dialogs. That includes PROSE: host names in comments, docs and test notes ('the server leg first switch', an operator device name) are hardcoded references too. Before claiming the tree machine-agnostic, `git grep -nIiwE '<node names>|<tailnet>.ts.net|100\.(6[4-9]|[7-9][0-9]|1[01][0-9]|12[0-7])\.'` at the landed sha, exclude only the repo's own clone URL, and report hits as a verdict table (functional vs prose). When you resolve a host the operator names (a typo, a short name), say it came from `tailscale status` — an unexplained concrete name reads as a repo reference and he will ask; answer such a question with the HEAD grep. A new host gets its own pane in the converge window (`tmux split-window -t <win>` + `select-layout tiled`); an sshd password prompt there is the operator's to type — say so and stop. Under `curl | sh` stdin is the script: dialogs need `</dev/tty` and whiptail provisioned from the pinned nixpkgs before the first switch (details: references/bare-box-docker-testing.md, interactive lane). Prove dialog UX in a fresh container through the real pipe shape before host rollout. A fleet join pairs only with the ONLINE members (`joined: N of M` names the shortfall) — when the offline member returns, re-run `workstation fleet` on the joining host to complete the pairing; verify the mesh from one place by curling every member's `:9902/fleet` and `:9900/.well-known/agent-card.json`.
- After an interrupted side-effecting call (orphan recovery, user interrupt), inspect before redoing: `git log`/`git status` in the worktree and the host checkout, `origin/main`, the tail of `switch.log`, running switch processes — the chain often completed (commit, push, pull, apply); re-running blind double-applies or reports stale state.
- Big inline commands (a multi-edit python heredoc chained with builds/tests) can trip the terminal's hardline payload block. Make each file edit a patch-tool call and run builds/tests as a separate short command.
- Python heredoc edits die silently on quote collisions: a string ending on a quote character (four quotes at the close) or `'''` inside the payload makes the write never land — the file stays clean while the edit 'succeeded' in your head. Use the patch tool for exact-string edits; if a heredoc is unavoidable, never end the python string on a quote char and assert on the POST-write file content.
- Nerd-font glyphs: never hand-derive codepoints from memory (`\U...` escapes produce lookalike emoji garbage that renders as 📛📚📜). Extract the exact bytes from the upstream docs (fetch the source, splice programmatically) and verify with a codepoint byte check (`grep -c $'\xf3\xb0\x8d\x9b'`) — a display-mangled grep pattern in your own command reads as zero matches and sends you fixing a file that is already correct.
- Formatter law in the editor payload: the substrate locks Prettier as the sole JS/TS formatter (stated in the payload's options.lua). A project on a different formatter (biome) owns the choice at the PROJECT layer — a project-root `.lazy.lua` importing the formatting extra plus a conform override — never a substrate-wide flip that breaks every other project. Verify with `:ConformInfo` in a project buffer, and check the formatter binary resolves from the project's node_modules.

## Nix substrate program

Durable conventions for the substrate (one nixpkgs, explicit module imports, domain-owned options, the machine file, upstream `programs.*`, container proofs): see references/nix-substrate.md. Hosts converge through generations + rollback; prerequisites are nix+daemon (host-owned on standalone-HM legs) and whiptail (ships with the substrate). System daemons on standalone-HM legs (tailscaled) are provisioned by the substrate: the domain's activation program writes its own marked `/etc/systemd/system/<unit>` over a GC-rooted store package, answers converged hosts without root and re-execs under sudo only on change, deferring with the exact command when elevation is unavailable. It NEVER removes another install: a package, snap or foreign unit already owning the daemon stops the provision with a message naming it (detection needs no root — run it before the sudo re-exec). Removing a host's previous install is a host-local one-off the operator runs (references/host-first-switch.md, 'A previous system-daemon install').
